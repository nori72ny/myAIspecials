# ORIGIN V1.5 — Creative / Visual Generation

Status: implementation branch foundation; **not yet a V1.5 completion claim**.

## Release intent

V1.5 turns visual requests into real, verifiable creative artifacts. A preview, an optimized prompt, or a provider URL alone is not a completed visual artifact.

The initial frozen scope is intentionally narrower than the eventual V1.5 product:

- verified static vector visual generation;
- self-contained SVG output;
- social-card, poster, and information-card compositions;
- square 1080×1080, portrait 1080×1350, story 1080×1920, and landscape 1200×630 presets;
- editorial, minimal, and split layouts;
- client-save-only artifact delivery;
- deterministic local generation with zero provider executions and zero external network requests.

This foundation does **not** claim:

- photorealistic raster image generation;
- diffusion/image-model execution;
- model-based image editing;
- video or 3D generation;
- V1.5 completion;
- best-in-class visual quality.

## Why the foundation is local SVG first

ORIGIN has a non-negotiable `$0 / freeOnly=true / paid fallback disabled` policy. As of 2026-09-16, OpenRouter's official image-generation documentation states that no image generation model currently has the `:free` suffix and that image generation uses paid catalog rates. Hugging Face Inference Providers expose small monthly credits, but provider inference itself is priced and can become pay-as-you-go; that is not equivalent to a provider execution with proven `costUsd=0`.

Therefore V1.5 must not reactivate the legacy `/api/generate-image` route with a paid model, silently consume credits, or return a prompt/URL while claiming a generated image.

Current evidence references:

- https://openrouter.ai/blog/tutorials/image-generation-models/
- https://openrouter.ai/collections/image-models
- https://huggingface.co/docs/inference-providers/pricing

Provider availability and pricing are volatile. Re-check them immediately before any future raster-provider integration.

## Public foundation API

### Status

`GET /api/creative/v1.5/status`

The status must distinguish the implemented vector foundation from unavailable raster/model capabilities. It reports:

- `releaseStage=verified-vector-foundation`;
- `generationMode=deterministic-local`;
- `externalNetworkRequests=0`;
- `providerExecutions=0`;
- `rasterImageGeneration=false`;
- `modelBasedImageEditing=false`;
- `freeOnly=true`;
- `costUsd=0`;
- `paidFallbackEnabled=false`.

### Generate

`POST /api/creative/v1.5/generate`

The server validates a bounded structured request, blocks detected sensitive input, generates SVG bytes, verifies the bytes, computes SHA-256, and returns the real artifact as a download.

The legacy-disabled `/api/generate-image` path is being migrated to a dedicated raster boundary. It remains fail-closed unless a server-only provider credential is configured, the exact audited model is present in the provider's live catalog with zero numeric price, and the completed request can be matched to provider usage evidence reporting `cost_usd=0` without paid-balance consumption. A vector artifact or prompt must never be substituted and presented as model-generated raster output.

## Raster candidate boundary

The current raster candidate is intentionally narrower than the eventual image product:

- provider adapter: Pollinations Gen API;
- audited model allowlist: `tomdacatto/sana` only;
- server-only `POLLINATIONS_API_KEY`;
- no browser exposure of provider credentials;
- live model-catalog price check immediately before generation;
- no automatic substitution to another model;
- HTTP 402 and paid/exhausted paths fail closed;
- returned MIME type must match PNG/JPEG/WebP magic bytes;
- output bytes are SHA-256 hashed and re-verified by the client;
- a recent matching provider usage record must report `cost_usd=0` and must not use `meter_source=pack`;
- if post-execution zero-cost evidence cannot be proven, the result is withheld;
- the UI must not fall back to a prompt when a real image was requested.

A configured credential and successful live exact-model generation are still required before ORIGIN may claim raster image generation is operational in production. Image editing, inpainting, outpainting, identity preservation, and reference-image workflows remain separate future gates.

## SVG security boundary

Generated SVG must be self-contained and bounded. Verification rejects or avoids:

- script elements;
- `foreignObject`;
- embedded image elements;
- `href` / `xlink:href`;
- CSS `url(...)`;
- `@import`;
- event-handler attributes;
- unbounded output bytes.

User strings are XML-escaped. Theme colors accept only six-digit hexadecimal values. No arbitrary SVG source is accepted from the request.

## Completion gates for V1.5

This foundation can merge only after exact-head tests, typecheck, build, security checks, and preview verification pass. However **V1.5 itself remains incomplete** until the following are separately implemented and evidenced:

1. creative UI/UX on mobile and desktop;
2. artifact preview/download flow that preserves isolation boundaries;
3. visual quality benchmark with a frozen rubric and diverse prompts;
4. accessibility checks, including meaningful artifact labeling;
5. copyright/safety handling appropriate to any model-based generation path;
6. if raster/model generation is added, live provider/model evidence proving zero price, privacy/ZDR policy, no paid fallback, exact served model, and zero reported cost;
7. image editing only after an equally verified execution path exists;
8. production exact-SHA release evidence.

If no raster provider satisfies the hard `$0` contract, ORIGIN must continue to expose raster generation as unavailable rather than weaken the policy.

## V1.4 benchmark isolation

V1.4 final held-out qualification is frozen against the current main revision. V1.5 engineering is therefore performed on a separate branch and must not move `main` before the first unseen V1.4 final corpus is frozen and run. This prevents a benchmark base-SHA mismatch and preserves provenance.
