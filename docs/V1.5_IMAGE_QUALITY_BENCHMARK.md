# ORIGIN V1.5 — Blind Image Quality Benchmark

Status: executable evaluation protocol. It does not claim current ORIGIN image quality has passed.

## Purpose

A successful API call is not an image-quality result. ORIGIN must prove that its delivered images are technically valid, follow the request, and compete with strong image systems under blinded evaluation.

## Frozen shape

The benchmark uses exactly 24 cases: 12 families × 2 unseen prompts.

Families:
1. photoreal scene
2. portrait / anatomy
3. product / commercial
4. food / material rendering
5. cinematic lighting
6. illustration style
7. anime / comic
8. social advertisement
9. poster / key visual
10. thumbnail
11. typography
12. infographic / UI visual

The plaintext prompts belong to the evaluator-owned sealed corpus. The public repository stores the protocol and scorer, not benchmark answers or reference outputs. Candidate development must not tune against held-out answers.

## Equal task rule

For every case:
- ORIGIN and references receive the same user request and target dimensions;
- use at least 3 strong reference image systems;
- outputs must finish within the predeclared execution budget;
- failed, blocked, quota-limited, unsafe, or technically invalid outputs remain in evidence and are not silently replaced;
- no hand-editing is allowed after a system returns its final user-visible image, except deterministic typography/compositing that is part of that product's declared normal workflow and is recorded before the round begins.

## Deterministic gate before judging

Every compared output must first pass:
- valid PNG/JPEG/WebP signature;
- requested dimensions;
- non-empty/nontrivial payload;
- decode success;
- clipping / density checks;
- output digest;
- safety and delivery-integrity checks.

A technically invalid output makes the case ineligible for a quality pass; it must not be hidden from the report.

## Blinding

Each case uses blind output keys such as A/B/C/D. The judge packet contains:
- case ID;
- family;
- prompt digest;
- dimensions;
- text requirement;
- blind output key and output digest.

It does **not** contain system ID, ORIGIN/reference role, provider, model, or product name.

Identity mapping is retained only by the evaluator and revealed to the scorer after judgments are frozen.

## Judges

At least 2 independent multimodal judges score every case.

Each output receives 0–4 scores on:
- prompt adherence;
- composition;
- subject integrity / anatomy / geometry;
- style execution;
- text fidelity or correct absence of unwanted text;
- artifact control;
- professional usefulness.

Each judge also chooses a first-choice output.

## Strict case comparison

ORIGIN is compared with the **best-scoring reference for each case**, not with an average weak baseline.

A case is a win only when:
- ORIGIN's mean score exceeds the strongest reference by at least 0.10; and
- ORIGIN's first-choice vote count is not below the strongest reference vote count.

A case is a loss when:
- ORIGIN trails the strongest reference by at least 0.10; or
- its first-choice vote count is below the strongest reference.

Everything else is a tie.

## Absolute quality floor

Before competitive thresholds can pass, ORIGIN must also meet:
- overall mean >= 3.35 / 4;
- prompt adherence >= 3.40;
- composition >= 3.30;
- subject integrity >= 3.30;
- style execution >= 3.20;
- text fidelity >= 3.20;
- artifact control >= 3.40;
- professional usefulness >= 3.40;
- zero critical failures.

## Competitive threshold

The round passes only with:
- exactly 24 cases;
- every family represented twice;
- >=3 reference systems;
- >=2 independent judges per case;
- >=50% wins;
- <=30% losses;
- >=60% non-loss;
- no criterion where ORIGIN's round mean is below the per-case strongest-reference mean;
- exact candidate SHA and SHA-256 evidence binding;
- evidence lifetime <=31 days.

## Command

```sh
npm run eval:image-quality -- <benchmark-evidence.json>
```

The scorer emits a blind-preference evidence object that can feed `origin.world-class-quality-gate.v1`.

## Improvement rule

A failed round is diagnostic evidence, not a reason to lower the gate.

For each losing case:
1. classify the failure: prompt understanding, composition, anatomy/geometry, material realism, text handling, artifacts, or usefulness;
2. reproduce the class on non-held-out development prompts;
3. improve Scene Planner / Prompt Compiler / provider routing / deterministic typography / semantic critic / repair loop as appropriate;
4. add regression coverage;
5. run a fresh sealed round.

The target is better user-visible work, not benchmark gaming.
