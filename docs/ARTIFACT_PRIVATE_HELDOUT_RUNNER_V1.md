# ORIGIN Artifact Private Held-Out Runner V1

Status: candidate-side execution runner for the 16-case blind Artifact quality round.

## What this runner measures

The runner starts from the same natural-language synthetic task prompt that a reference system would receive. It does not hand ORIGIN pre-written report content.

For every private case it executes:

1. private natural-language prompt -> the real local `/api/chat` route;
2. verified zero-cost provider response -> the real Artifact V1.2 or Web Builder V1.3 route;
3. generated bytes -> deterministic technical validation;
4. exact candidate artifact bytes + sanitized evaluator evidence -> one-shot workflow artifact.

This means content generation and artifact rendering are both inside the candidate path.

## Private corpus

The evaluator supplies `ORIGIN_ARTIFACT_PRIVATE_CORPUS_GZIP_B64` as a GitHub Actions secret. The corpus must:

- contain exactly 16 synthetic/non-user-data tasks;
- contain exactly 2 cases from each of the 8 benchmark families;
- cover every challenge tag at least twice;
- bind every prompt with SHA-256;
- bind the full private task, including technical oracle values, with a task digest;
- match the exact candidate SHA;
- define one common execution budget.

The benchmark secret must not contain real user data, proprietary material, credentials, personal information, or production secrets.

## Equal-task boundary

The private natural-language prompt is the equality anchor for comparison. ORIGIN receives that prompt first through `/api/chat`.

Office/PDF/CSV/Markdown cases then render the generated answer through `/api/artifacts/v1.2/generate`. Web cases render the generated answer through `/api/builder/v1.3/generate` using a deterministic product-side transformation that does not read the evaluator's required-content oracle.

The `requiredContent` oracle is used only after generation for technical validation and never injected into the model or renderer.

## Zero-cost and privacy gate

Every successful chat execution must prove:

- `freeOnly=true`;
- actual and estimated cost = USD 0;
- exactly one provider attempt;
- requested and served model identity match the permitted canonical identity;
- provider fallback disabled;
- data collection denied;
- ZDR required;
- usage cost = USD 0.

No provider retry is performed by the production provider client. Rate limits and provider failures remain benchmark failures.

## Technical validation

Candidate bytes are not trusted merely because an endpoint returned HTTP 200. The runner checks:

- exact SHA-256 against the delivery header;
- MIME and binary signature;
- Office/Web ZIP package structure or PDF/text structure;
- required task content in the actual output bytes;
- task-specific checks such as heading structure, table structure, multi-slide output, responsive CSS, offline runtime, editable source, or multi-section output;
- no-corruption contract;
- free-only delivery headers;
- editability/source structure;
- layout or responsive structure.

The scorer later requires every technical boolean to be true. A technically invalid completed file remains a technical failure rather than being silently discarded.

## One-shot execution

Workflow: `.github/workflows/artifact-private-heldout-v1.yml`.

It is manual-only and main-only. Before any provider request, preflight:

- validates the sealed corpus in runner memory;
- verifies candidate SHA == `github.sha` == checked-out HEAD;
- checks for a prior corpus-digest start marker;
- writes the one-shot start marker before provider execution.

Once a corpus starts, it must not be rerun until it happens to produce favorable outputs.

## Sanitized outputs

The workflow uploads:

- `public-tasks.json`: case IDs, family/tags, prompt digest, expected format, task digest;
- `candidate-evidence.json`: candidate output digests, technical evidence, duration, status, safe provider/model identity, failure code;
- `candidate-summary.json`: attempted/completed/technical-pass counts and run blockers;
- `candidate-artifacts/`: exact generated candidate files under opaque case IDs.

It does not upload the sealed corpus, prompt text, or required-content oracle.

Candidate artifacts themselves are intentionally retained because independent blind judges must inspect the actual work product. That consumes the held-out round; engineering must not tune against the consumed cases afterward.

## What remains after this runner

An independent evaluator must run the exact same frozen prompts/time budget against three fixed strong reference systems, technically validate those outputs, assign opaque blind keys, obtain at least two independent source-blind judges, and assemble the complete `origin.artifact-blind-benchmark.v1` packet.

Then run:

```sh
npm run eval:artifact-blind-quality -- <complete-blind-evidence.json>
```

A candidate-side runner completion alone is not evidence that ORIGIN is better than other systems.
