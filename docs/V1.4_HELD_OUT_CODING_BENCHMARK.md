# V1.4 Held-out Agentic Coding Benchmark

## Purpose

This benchmark is separate from `scripts/compare-coding-search-v14.ts` and the synthetic search regression set. Search quality remains a component-level regression signal; this benchmark evaluates end-to-end coding evidence.

The minimum acceptance axes are:

1. held-out identity: private task packet digest, exact base commit, and equal time budget;
2. multi-file editing: at least two required production paths changed while protected evaluator/hidden-test paths remain untouched;
3. verification: the final attempt truthfully passes typecheck, lint, test, and build, with no Git publication or deployment side effect;
4. failure recovery: recovery-designated tasks must show a failed verification attempt followed by a materially later verified attempt.

A task is solved only when all four axes pass.

## What stays private

The repository contains the scorer, runner boundary, corpus parser, and public protocol only. It must not contain the held-out prompt, expected solution, hidden tests, or reference patch.

For each private task, the evaluator prepares a packet outside the participant-visible repository and records only the public projection:

- opaque task ID;
- SHA-256 digest of the private task packet;
- exact base commit SHA;
- equal wall-clock budget;
- required production paths for scoring;
- protected evaluator paths;
- whether failed-check recovery is required.

The participant receives the private goal only inside the trusted runner. The scoring library receives no private prompt, hidden-test source, or expected patch. Hidden tests are materialized only after the coding session terminates, so they cannot enter the model context or repair loop.

## Run evidence

Each participant run records:

- participant, provider, and model identifiers;
- exact base SHA and private task digest;
- actual duration and cost;
- every bounded attempt's changed paths and four verification summaries;
- terminal state and final changed paths;
- truthful Git publication/deployment flags.

Failures, blocks, cancellations, provider quota failures, and regressions stay in the denominator. Do not drop unsuccessful attempts.

## Equal-comparison rule

Comparative runs must use the same private task packet, base commit, hidden tests, time budget, and evaluator version. A different base SHA, task digest, or over-budget run fails the held-out identity axis rather than being silently normalized.

This harness does not claim Claude Code parity. It creates the evidence boundary needed to run that comparison without tuning ORIGIN on the held-out set.

## Public scorer

`src/agent/heldOutCodingBenchmarkV14.ts` is a deterministic scorer. It intentionally has no model/provider call, shell access, repository mutation, network access, or hidden-task fixture embedded in source.

`src/agent/heldOutCodingBenchmarkV14.test.ts` uses public synthetic fixtures only to verify the scorer's fail-closed behavior. Those fixtures are not benchmark tasks and must never be reported as model performance.

The offline scorer remains available as:

```sh
npm run eval:heldout-coding -- <task.json> <run.json>
```

## Private corpus bundle

`src/agent/heldOutCodingPrivateCorpusV14.ts` supports a private corpus containing up to 16 task packets. The corpus is gzip-compressed and base64-encoded before it is stored as a GitHub Actions secret. The parser fails closed on malformed base64/gzip/JSON, oversized compressed or expanded payloads, duplicate task IDs, invalid packets, and unknown dispatch task IDs.

The preferred secret is `ORIGIN_HELDOUT_CORPUS_GZIP_B64`. The legacy single-task `ORIGIN_HELDOUT_TASK_PACKET_B64` remains supported as a fallback so existing evaluator configuration does not break during migration. When both exist, the corpus is authoritative.

A private evaluator can encode a corpus without committing its plaintext:

```sh
node --import tsx scripts/encode-held-out-corpus-v14.ts /private/path/corpus.json
```

The encoder validates every packet, gzip-compresses at level 9, enforces the hosted secret-size budget, and prints task IDs, byte counts, a SHA-256 corpus digest, and the secret value. The plaintext corpus and generated secret value must stay outside the public repository and CI logs.

The corpus JSON shape is:

```json
{
  "version": "origin-held-out-private-corpus-v1",
  "tasks": [
    {
      "version": "origin-held-out-private-task-v1",
      "id": "opaque-task-id",
      "baseSha": "40-hex-commit-sha",
      "timeBudgetMs": 120000,
      "requiredChangedPaths": ["src/a.ts", "src/b.ts"],
      "protectedPaths": ["tests/__origin_heldout__/private.test.ts"],
      "recoveryRequired": true,
      "goal": "private evaluator task prompt",
      "hiddenTests": [{ "path": "private.test.ts", "content": "private test source" }]
    }
  ]
}
```

## Trusted hosted runner

`src/agent/heldOutCodingTrustedRunnerV14.ts` validates an evaluator-owned private packet, hashes the entire packet deterministically, derives the public task projection, converts the bounded Coding session audit into benchmark attempts, runs evaluator-owned hidden verification only after the agent terminates, and submits the resulting public evidence to the same scorer.

`scripts/run-held-out-coding-trusted-v14.ts` is the hosted controller. It:

1. selects one packet by opaque `task_id` from the compressed private corpus, or falls back to the legacy single packet;
2. immediately removes the encoded corpus/packet from `process.env` and gives the model/provider adapter only the minimum provider configuration;
3. checks out the exact evaluator-selected base SHA into a disposable Git worktree;
4. requires the dependency lock to match the trusted controller dependency snapshot;
5. invokes the bounded V1.4 Coding Agent with at most three repair rounds;
6. runs typecheck, lint, test, and build sequentially in fresh Docker copies;
7. after the Coding session terminates, materializes private hidden tests and runs them in another fresh Docker copy;
8. emits only the public task, run, and score JSON files; and
9. removes the disposable worktree.

Both normal checks and hidden checks run with network disabled, a read-only container root and dependency mount, dropped Linux capabilities, `no-new-privileges`, bounded CPU/memory/PIDs, a stripped environment, fixed commands, and hard per-check timeouts. Hidden-test source and raw hidden-test output are not emitted in benchmark evidence or fed back to the agent.

## GitHub Actions boundary and batch mode

`.github/workflows/held-out-coding-benchmark-v14.yml` is manual-only (`workflow_dispatch`) and is intentionally not a pull-request workflow. The optional public input is only an opaque `task_id`.

When `task_id` is supplied, the workflow runs only that task. When it is left blank, `scripts/select-held-out-task-ids-v14.ts` reads the private corpus inside the trusted selector job and exposes only the opaque IDs to a sequential matrix. `max-parallel: 1` keeps free-provider load bounded. Prompts, hidden tests, and corpus contents never become matrix values or public workflow inputs.

The trusted evaluator configures:

- preferred: `ORIGIN_HELDOUT_CORPUS_GZIP_B64`, one compressed private corpus used for multiple task IDs;
- migration fallback: `ORIGIN_HELDOUT_TASK_PACKET_B64`, one base64 private task packet;
- existing: `OPENROUTER_API_KEY`, the provider credential used by the zero-cost Coding path.

A full private corpus therefore requires one secret configuration and one manual workflow dispatch. Each matrix job checks out with persisted Git credentials disabled, prepares the fixed Docker verifier image, runs the trusted controller, and uploads only:

- `held-out-task-public.json`;
- `held-out-run.json`;
- `held-out-score.json`.

Git/PR publication and deployment remain outside this benchmark's authority.

## Remaining acceptance work

The runner implementation is not itself benchmark evidence. Before any Claude Code parity or superiority claim:

1. freeze an evaluator-owned private corpus containing multiple navigation, multi-file repair, feature-addition, regression-recovery, and build-repair tasks;
2. configure the compressed corpus outside the public repository and run the frozen batch from each exact base commit;
3. run ORIGIN and comparison agents under the same task packet, hidden tests, evaluator version, and time budget;
4. retain every solved, failed, blocked, quota-limited, and regressed run in the denominator;
5. report solved/attempted, regression counts, median duration, provider/model identity, actual cost, and quota failures; and
6. make comparative claims only from that frozen evidence.
