# V1.4 Agentic Coding OS

## Agreed release sequence

V1.1 Grounded Research → V1.2 real file artifacts → V1.3 Web / Application
Builder → V1.4 Agentic Coding OS → V1.5 Creative / Visual Generation →
V2 Unified Production OS.

V1.4 targets repository understanding, multi-file editing, real checks,
debugging and bounded repair, Git/PR delivery, deployment, and audit. Comparison
with Claude Code is a goal, not a measured result.

## Current increment: trusted-worker session engine

`src/agent/codingSessionV14.ts` connects the existing race-resistant reader and
exact-match delta editor to a planner and verification adapter supplied by a
trusted worker. It accepts an explicit dedicated repository root and at most
12 existing files, bounds input/patch bytes, preflights a batch, rejects stale
snapshots, and permits at most three repair rounds. A session is verified only
when typecheck, lint, tests, and build all report zero exits without timeouts.
Changed files and their hashes are recorded; source content and raw diagnostics
are not retained in the returned journal. The module does not call AI providers.

The caller must own a dedicated, approved workspace. The lock is process-local;
it is not shared storage or a distributed lease. A partial failed batch is
reported through `changedPaths` and the audit; there is no automatic rollback or
durable checkpoint. A later mutation during checks blocks success. Existing
files only are supported in this increment.

## Required before public autonomous execution

- A dedicated runner with OS/process/network isolation, job deadline, bounded
  output and process-tree termination. Sanitizing environment variables alone
  is **not** a sandbox. Do not expose the existing `process.cwd()` writer or
  verification runner to user-supplied repositories on the production app.
- Live validation of the zero-cost planner adapter and its structured patches.
  Repository content is data, not authority to change execution policy.
  Current tests use controlled model responses, not a live model benchmark.
- A durable job store and independent worker leases, authenticated ownership,
  cancellation, restart recovery and retention/deletion controls.
- Separately scoped GitHub credentials, approved target repository/ref, branch
  creation, diff review, CI evidence and exact-head PR delivery.
- Deployment authorization, a zero-cost deployment adapter and production SHA
  verification. No production secret may be included in the coding sandbox.
- Product UI with truthful pending/running/blocked/failed/verified states and
  cancellation. V1.4 must not be labeled complete while these are unavailable.

## Release evidence

Require real temporary-repository tests including multi-file edits, a failing
test repaired and rerun, stale snapshots, out-of-scope/protected paths, symlink
escapes, concurrent work and exhausted repairs. Full CI and an independent
security review must target the release candidate. Git/PR and deployment
verification must be evidenced separately from local edit/check success.

The existing V1.3.1 authenticated publication smoke remains blocked by the
missing GitHub production-environment approval secret; this work does not mark
that test as passed or change its credential boundary.
# Hosted runner increment (no personal server)

## Model-driven repair increment

`runCodingAgentV14` connects the session engine to the existing zero-cost
provider client. The trusted controller supplies an isolated verification
adapter. Optional `contextPaths` supply tests/callers without granting write
access; all inspected files are rechecked after verification. Failed checks
can supply bounded diagnostics, sanitized before repair and omitted from audit
records. Model output is strict JSON with unique, in-scope, exact-match edits.
Malformed output and unverified costs stop execution. No paid fallback is added.

This adapter has protocol tests with controlled responses, not measured live
model performance. No model key is available in the development workspace.
The offline CI regression suite deliberately does not use provider credentials.
The production controller/runner transport, UI and Git publishing remain pending.

### Quality acceptance criteria

Claude Code parity and world-leading generation quality are goals, not release
claims. Before making comparisons, freeze a held-out task set covering repository
navigation, multi-file bug fixes, feature additions, regressions and build repair;
run both systems against the same base commits, hidden tests and time budgets.
Report solved/attempted tasks, regressions, median duration, model/provider IDs,
actual cost and quota failures. Include every failed or blocked attempt, and
retain the exact patch and check provenance. Do not let the agent edit hidden
tests or tune on the held-out set. Current fixture tests only establish mechanics.

Remaining milestones: repository discovery and new-file edits; durable jobs with
cancel/resume; authenticated UI dispatch and result retrieval; scoped branch/PR
publication; deployment evidence; live model benchmark. Larger autonomy budgets
must follow these controls rather than merely increasing retries.

`coding-session-sandbox.yml` runs this public repository's session regression
suite on a standard GitHub-hosted Ubuntu VM. Private repositories are skipped.
There is no cache or artifact upload, larger runner, or paid fallback in this
workflow. Public standard runner minutes are free under GitHub's documented
billing policy: https://docs.github.com/en/billing/concepts/product-billing/github-actions.

Dependency preparation has network access but disables npm lifecycle scripts.
The test container runs without network, credentials, Docker socket, or Git
metadata; its root and dependencies are read-only, and it uses an unprivileged
user, dropped capabilities, bounded memory/processes and a five-minute deadline.
Container removal terminates remaining processes after timeout. Only temporary
source copies are writable. The Node image uses a version tag, not an immutable
digest; dependency supply-chain review remains a production runner requirement.

This is CI evidence for the coding-session core, not an arbitrary-code service
or a production dispatch adapter. Public workflow logs must never receive private
tasks or source. User ownership, authenticated dispatch, live planner validation,
durable job state and result retrieval still need implementation before enabling
remote coding from the ORIGIN UI. No personal server is required for this route.
