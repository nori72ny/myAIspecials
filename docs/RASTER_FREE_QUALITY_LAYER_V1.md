# Raster Free Quality Layer V1 — $0.00 画像生成の再有効化と品質最大化

Status: 実装済み（PR `feat/raster-cloudflare-free-reenable`）。実アカウントでの生成は未実施（UNVERIFIED）。
根拠レポート: `IMAGE_GEN_BENCHMARK_2026-11-06.md`（スコア 0.5/10 の現状評価と再有効化条件）。

## 1. 再有効化の $0.00 証明（3点セット）

Cloudflare Workers **Free プランには超過課金の仕組みが存在しない**（上限超過は課金ではなくエラーになる、公式料金ページで確認）。この構造的性質の上に、リクエスト単位で次を全て満たした場合のみ画像を配信する。

1. **プラン証明**（既存 `verifyWorkersFreePlan` を流用）: アカウントが bundled（Free）利用モデルであり、有料 Workers サブスクリプションが無いこと、対象モデルのスキーマが取得できることを推論前に API で確認。1つでも不明なら fail closed。
2. **クォータ事前チェック**（新規 `cloudflareRasterFreeQuotaV15`）: GraphQL Analytics で当日の実測 Neuron 使用量を取得し、価格証拠（公式単価カタログ、検証窓あり・失効時は停止）の決定論的上限見積もりで予約が残枠に収まる場合のみ推論する。品質層の全消費（候補数＋リトライ分）も事前に予約する。
3. **生成後の使用量照合**（同上）: 生成後に使用量を再取得し、実測デルタが「0 < デルタ ≤ 予約上限」であることを確認。照合できない画像は生成済みでも**配信しない**。

未設定時（Cloudflare 資格情報なし）は従来通り 503 `RASTER_GENERATION_DISABLED_ZERO_COST_POLICY` で fail closed。Pollinations は残高不足時に有料残高から引かれる設計で構造的証明が不可能なため、本経路では**使用しない**。

## 2. モデル選定（再検証結果）

| モデル | 1024×1024 の単価 | 1日の目安 | 画質の位置づけ |
|---|---|---|---|
| FLUX.2 Klein 4B（既定） | 実測換算 約110 Neurons（予約見積もり 126） | 約80〜90枚 | Klein 9B より下位。速度・量で優位 |
| FLUX.2 Klein 9B（opt-in） | 1,363.64（初回1MP一律）＋ 181.82/追加MP → 約1,373 Neurons | 約6〜7枚 | Artificial Analysis Elo 940（オープンウェイト最高水準）。ただし GPT Image 級（約1,196）とは約256pt差 |
| FLUX.1 Schnell / SDXL 等 | より安い | より多い | FLUX.2 世代より画質が明確に下位のため不採用 |

**既定を 4B とする理由**: 9B は1枚あたり約11倍の消費で、best-of-N＋リトライ（後述）と両立しない。4B の上で「プロンプト強化＋候補選択＋リトライ」を回す方が、Neuron あたりの**配信品質**が最も高くなる。9B は `ORIGIN_CLOUDFLARE_IMAGE_MODEL` での明示 opt-in として価格モデル込みで有効化可能にした（単一候補中心の運用を想定）。

## 3. 品質最大化層（すべて $0.00 証明の内側）

1. **プロンプト自動強化**（`rasterPromptEnhancementV15`、fail-soft）: 既存の無料チャット LLM（OpenRouter `:free`、ZDR strict ルーティング、無料モデル証拠カタログの鮮度チェック付き）で、構図・質感・照明・色彩を具体化した生成向けプロンプトに書き換える。キー未設定・証拠失効・HTTP エラー・出力不正のいずれでも**元のプロンプトで継続**する。OpenRouter の無料日次枠（チャットと共有プール）を1リクエストにつき1回だけ消費する。`ORIGIN_RASTER_PROMPT_ENHANCEMENT=false` で無効化可能。
2. **best-of-N**（オーケストレータ）: 既存の候補ポリシー（`candidatePolicyForRasterRequestV15`）が品質クリティカル用途（広告・商品・ポスター・サムネイル・ポートレート等）に推奨する2候補を上限に、クォータ残量で可能な候補数を動的に決定。各候補に構造批評（ローカル）＋セマンティック批評（Moondream、同一無料枠）を適用し、合格候補のうち最高スコアを配信する。
3. **自動リトライ（1回まで）**: 全候補が不合格で、リトライ分の予約が事前に確保できている場合のみ、最良の不合格候補の批評所見（要約＋指摘）をプロンプト改訂とネガティブプロンプトに織り込んで1回だけ再生成する。
4. **セマンティック批評ゲートの接続**: 従来 `enabled: false` だった3層批評のうち、構造批評とセマンティック批評をサーバー側の配信ゲートとして接続した。技術ピクセル批評はサーバー側デコーダが無いため、従来通りクライアント側（`inspectRasterBlobV15`）で実行される接続点を維持し、サーバーゲートには含めない（理由は PR 本文に明記）。

## 4. 1日の想定消費 Neurons（1024×1024・4B の試算）

| 形態 | 予約（最悪値） | 実測想定 | 1日の目安 |
|---|---|---|---|
| 単一候補（リトライ予約込み） | 764（=(126+256)×2） | 約175〜290/リクエスト | 保証ベース 約13件、実測想定 約34〜57件 |
| best-of-2（リトライ予約込み） | 1,146（=(126+256)×3） | 約350〜580/リクエスト | 保証ベース 約8件、実測想定 約17〜28件 |
| 9B 単一候補（リトライ予約込み） | 3,258（=(1,373+256)×2） | 約1,450〜1,630/リクエスト | 約3〜6件 |

セマンティック批評の実消費は未実測のため予約は保守的に 256 Neurons/回と置き、実測デルタは照合で常に検証される（予約超過は配信停止）。

## 5. 正直な限界

- 実アカウントでの生成・実消費 Neurons・GraphQL 使用量スキーマの実在形式は**未検証**（ライブ資格認定が別途必要）。検証はモックで完結させてあり、不一致は全て fail closed 側に倒れる。
- 品質層は「無料制約の中で配信品質を最大化」するものであり、基盤モデル自体の画質差（Klein 9B Elo 940 vs GPT Image 約1,196、写真の実在感・文字描画・東アジア系の顔の弱点）は解消しない。競合水準の画質には有料モデルが必要であり、$0.00 ポリシーの下では到達できない。
- 価格証拠には検証窓（reviewAfter）があり、失効すると生成は自動停止する。定期的な再確認が運用前提。
