# ORIGIN 6回答比較監査 — 回答品質・AI UX

- 監査日: 2026-08-16 JST
- 対象: ORIGIN自身の回答1件と、利用者から共有された他AI回答5件
- 目的: 将来予測をそのまま製品仕様にせず、現行実装と照合して採用可否を判断する

## 結論

ORIGINの現在の優位点は、見栄えの良い長文ではなく、実行証拠に基づく表示にある。現行実装は、未確認の出典、独立確認の未実施、未接続機能、費用、実際のモデル経路を区別しており、共有回答にある「信頼の設計」の多くをすでにコードで実現している。

不足していたのは、依頼ごとに回答形式を変える明示的な品質方針、回答後に利用者が低摩擦で修正方向を指定できる導線、回答コピー、重複結論の抑止である。本変更ではこの4点を実装する。

## 比較結果

| 評価軸 | ORIGIN現行 | 他AI提案から得た示唆 | 判断 |
|---|---|---|---|
| 事実と推測の分離 | 実装済み | 全回答で重要視 | 維持・品質方針へ明記 |
| 出典の真偽表示 | URL形式確認と本文確認を分離済み | 引用カード、Claim-to-source対応 | 現行方式を維持 |
| 数値信頼度 | 根拠のない数値を表示しない | 数値より説明的表示を推奨する回答あり | 数値化しない |
| 結論先行・可読性 | 実装済みだが、Markdown見出し次第で結論が重複し得る | Decision Object、段階的開示 | 重複防止を実装 |
| 回答タイプ最適化 | 意図分類はあるが品質ルールとの接続が弱い | 調査・判断・成果物で表示を変える | 回答品質ポリシーを実装 |
| 回答後の修正 | 自由入力のみ | 低摩擦フィードバック、目的変換 | コピー・評価・改善アクションを実装 |
| 作業状況 | 経過時間と段階ラベルを表示済み | Activity Rail | 実イベントがない段階で完了チェックは出さない |
| 複数AI検証 | 必要性判定と未実施表示あり | Generator/Critic/Verifier分離 | 無料で独立性を証明できる経路ができるまで未実施を明示 |
| Generative UI | 成果物型のスキーマのみ | 比較表、グラフ、フォームの動的表示 | 検証済み部品に限定して将来拡張 |
| 自律実行 | 未実装を完了表示しない | 停止、承認、復旧、権限表示 | 実行基盤の導入時に必須条件とする |

## 今回採用した改善

1. **回答品質ポリシー**
   - direct / decision / deliverable / research の4形式を意図と能力から決定する。
   - basic / evidence-required / independent-review-required の3確認レベルを、信頼度ではなく必要な確認工程として扱う。
   - correctness、relevance、completeness、freshness、evidence、calibration、actionability、clarity の8軸を送信前確認に追加する。

2. **Decision Object型の回答規律**
   - 判断依頼は「推奨 → 決め手 → トレードオフ → 不確実性 → 次の行動」の順にする。
   - 最後に結論を再掲せず、未完の誘い文句や途中の文で終わらせない。

3. **利用者主導の回答改善**
   - 回答コピーを追加する。
   - 役に立った／改善が必要の評価を追加する。
   - 改善が必要な場合のみ「読みやすく整理」「精度を再確認」「別案と比較」を段階表示する。
   - 評価記録は回答本文を保存せず、端末内にID・評価・時刻のみ最大100件保存する。

4. **結論重複の防止**
   - 本文が「## 結論」「Conclusion」「Bottom line」から始まる場合、構造化された結論カードを重ねて表示しない。

## 採用しなかった提案

- **視線、疲労度、マウス挙動の常時取得**: 利用価値に対してプライバシー侵害と誤推定のリスクが大きい。
- **推論全文の表示**: 内部思考ではなく、実行状況、使用ツール、根拠、未確認事項を表示する。
- **根拠のない95%等の信頼度**: 疑似精度になり、誤った安心を与える。
- **回答ごとの無条件マルチAI実行**: 遅延、無料枠消費、同じ誤りの増幅がある。高リスクまたは明示依頼時に限定する。
- **自由生成UI**: アクセシビリティ、予測可能性、安全性を損なう。型付き・検証済みコンポーネントのみを組み合わせる。
- **時間経過だけで完了工程を表示**: 実行証拠のない進捗表示になるため採用しない。

## ORIGINの優位点と弱点

### 優位点

- 実行していない検索、レビュー、成果物生成を完了扱いしない。
- AIが提示したURLと、本文・更新時点・主張対応まで確認した出典を区別する。
- 回答表示と実行経路の確認状態が矛盾した場合、回答を非表示にする。
- 無料利用と実際に使用されたモデル経路を実行後にも確認する。
- モバイル用に長いMarkdown表をリストへ変換し、外部画像を自動読込しない。

### 弱点・残課題

- 最新情報検索は未接続であり、現在情報の網羅性では検索対応AIに劣る。
- 独立した別AIレビューを無料条件内で実行できる経路は未接続である。
- 動的な表、グラフ、文書、ワークキャンバスはスキーマのみで、実成果物レンダラーは限定的である。
- 端末内フィードバックは即時再回答には使えるが、サーバー側の継続的評価基盤にはまだ接続していない。

## 次段階の優先順位

1. 一次情報を取得し、主張単位で引用検証できる検索経路
2. 独立性を証明できるCritic/Evidence Checker経路
3. エラー種類ごとの部分再実行と復旧ポイント
4. 比較表・グラフ・文書を型付きで表示するGenerative UI
5. False Completion Rate、修正率、再作業率、最初の有用結果までの時間の計測

## 注意

共有回答に含まれる外部研究、企業機能、将来製品への言及は、この監査では一次資料による再確認を行っていない。したがって、具体的な製品名や研究結果ではなく、複数回答に共通する設計原則と現行コードで検証できる差分だけを採用判断に使用した。
