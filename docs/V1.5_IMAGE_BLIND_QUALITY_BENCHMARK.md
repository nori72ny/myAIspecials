# V1.5 Image Blind Quality Benchmark

Status: executable evaluation protocol. This does **not** claim current ORIGIN image generation already exceeds other systems.

## Purpose

This benchmark measures user-visible image quality, not whether an endpoint merely returned bytes.

A Release 2 raster path can be operational before this benchmark passes, but it must not be described as quality-complete or superior to leading image systems until the exact candidate passes this benchmark.

Schema: `origin.image-blind-benchmark.v2`.

## Frozen shape

The official round contains exactly 24 sealed cases: 8 families × 3 cases.

Families:
- photograph / scene
- portrait / anatomy
- product / commercial
- advertisement / social
- poster / key visual
- thumbnail
- illustration / style
- infographic / UI

The actual prompt text is frozen outside participant-visible source. Public evidence records the case ID and prompt SHA-256.

Every round must also cover each of these hard challenge tags at least twice:
- text
- hands/anatomy
- material realism
- complex lighting
- counting/layout constraints
- small-size readability
- style fidelity
- information density

This avoids a benchmark that wins only on easy photorealistic scenes while missing the tasks users actually request.

## Equal-task rule

For each case ORIGIN and the **same frozen 3 reference-system/version identities** receive:
- the same user request;
- the same target size/aspect intent;
- the same declared time/execution budget;
- equivalent access to any reference image or other allowed input.

When a participant API exposes only provider-native discrete resolutions/aspect ratios, its normalization policy must be frozen before the round and independently validated. The V1.6 ORIGIN publication candidate uses provider-native 1K output at the nearest supported aspect ratio and accepts at most 3% aspect-ratio error. This policy may not be changed case-by-case after seeing outputs.

The three reference identities are frozen at round level and may not be swapped case-by-case. Each output records completed/blocked/failed/quota-limited status and duration. Over-budget or non-completed runs remain explicit blockers rather than being silently rerun until a favorable sample appears.

Failed, blocked, quota-limited, unsafe, or invalid outputs remain in the evidence packet. They must not be silently replaced.

No manual retouching is allowed after the product returns its final user-visible output. A deterministic typography/compositing step is allowed only if it is part of that product's normal declared workflow before the round begins.

## Deterministic pre-qualification

All 4 compared outputs—not only ORIGIN—must pass:
- PNG/JPEG/WebP signature validation;
- the participant's frozen dimension/aspect policy against the common target intent;
- structural critic;
- technical pixel critic;
- safety checks;
- delivery-integrity check;
- SHA-256 output binding.

A technically invalid comparison set fails closed instead of giving either side an unfair advantage.

## Real blinding

Each output receives an opaque key such as A/B/C/D.

The judge packet contains only:
- case ID;
- family and challenge tags;
- prompt digest;
- dimensions;
- whether exact text is required;
- blind output key;
- output SHA-256.

The judge packet does **not** expose:
- ORIGIN/reference role;
- product/system name;
- provider/model name;
- hidden system identity.

The evaluator retains the identity mapping separately and reveals it to the scorer only after judgments are frozen.

## Independent judges

Every case requires at least 2 independent multimodal judges.

Each judge scores **every blind output** from 0–4 on:
1. prompt adherence
2. composition
3. subject integrity / anatomy / geometry
4. style execution
5. text handling or correct absence of unwanted text
6. artifact control
7. professional usefulness

Each judge also records one blind first-choice output.

A judgment is invalid if it omits an output, adds an unknown output, uses an invalid score, or references an invalid blind key.

## Strongest-reference comparison

ORIGIN is compared against the **strongest reference output on each individual case**, not against an average baseline.

For each case:
- average every judge's axis scores for each blind output;
- choose the highest-scoring reference output as that case's comparison target;
- calculate ORIGIN's average score versus that strongest reference;
- compare first-choice vote counts.

A case is a **win** only when:
- ORIGIN leads the strongest reference by at least 0.10 points; and
- ORIGIN's first-choice count is not below the strongest reference.

A case is a **loss** when:
- ORIGIN trails the strongest reference by at least 0.10; or
- ORIGIN's first-choice count is below the strongest reference.

Everything else is a tie.

## Absolute quality floor

Competitive preference alone is insufficient. ORIGIN must also meet:
- overall mean >= 3.35 / 4
- prompt adherence >= 3.40
- composition >= 3.30
- subject integrity >= 3.30
- style execution >= 3.20
- text handling >= 3.20
- artifact control >= 3.40
- professional usefulness >= 3.40
- zero critical failures

This prevents a "best of weak outputs" result from qualifying.

## Competitive acceptance

The round passes only if:
- exactly 24 cases are present;
- each family has exactly 3 cases;
- every challenge tag appears in at least 2 cases;
- every compared output passes deterministic pre-qualification;
- every case has exactly 1 ORIGIN output + 3 distinct reference outputs;
- every case has >=2 unique valid judges;
- overall win rate >=50%;
- overall loss rate <=30%;
- overall non-loss rate >=60%;
- every family non-loss rate >=60%;
- no rubric axis has an ORIGIN round mean below the per-case strongest-reference mean;
- exact candidate SHA, evaluator SHA, sealed-corpus SHA-256, fixed ORIGIN/reference system identities, equal execution budget, and complete evidence SHA-256 are retained;
- evidence is current and expires within 31 days.

All failures stay in the denominator.

## Relationship to the world-class gate

The scorer emits a `worldClassEvidence` object compatible with:

```sh
npm run eval:world-class-quality -- <evidence.json>
```

A passing image benchmark is only the image-domain input. The overall world-class gate separately requires current evidence for answer quality, Coding, general Agent behavior, and artifacts.

## Executable scorer

```sh
npm run eval:image-blind-quality -- <evidence.json>
```

The evaluator packet must use the v2 schema. The script exits non-zero when any blocker remains.

## Improvement loop

A failed round is diagnostic evidence, not a reason to lower the gate.

For each losing case:
1. classify the failure: intent understanding, composition, anatomy/geometry, material realism, lighting, style fidelity, text handling, artifacting, or usefulness;
2. reproduce that failure class on non-held-out development prompts;
3. improve the responsible layer: Scene Planner, Prompt Compiler, provider routing, deterministic typography, Semantic Critic, repair loop, or delivery UX;
4. add deterministic regression coverage;
5. freeze a new unseen comparison round;
6. rerun without tuning on the held-out answers.

The target is stronger real work, not benchmark gaming.

## Safety and cost

Benchmark score never overrides:
- the declared cost policy for the route being evaluated;
- no undeclared paid fallback;
- server-only secrets;
- fail-closed provider verification;
- least-privilege external access;
- owner approval boundaries.

The V1.5 Cloudflare route remains a zero-cost-only path and must fail closed rather than silently substitute a paid provider.

The V1.6 world-class publication candidate is a separate paid-capable route. Its private evaluation requires explicit paid-evaluation approval plus a hard per-image cap and a hard total-round cap. Paid evaluation evidence does not itself enable Production or qualify a SHA; exact-SHA blind-comparison success is still required.
